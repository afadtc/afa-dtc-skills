# WhatsApp 与 RCS 富媒体分册（消息营销引擎 · 与 SMS 主线并行的第二合规体系）

> 本文件为消息营销模块的内部参考文件。如需整理为用户可见交付物，必须删除内部路由标签、模块代号和系统字段。
>
> ⚠️ **合规隔离警示**：本分册（WhatsApp = Meta 商业政策 / 模板审核 / 24h 会话窗口；RCS = 运营商+设备体系）与本模块 SMS 主线（TCPA / 10DLC / 运营商限流）是**两套互不通用的合规逻辑**——不得把 TCPA 静默时段、10DLC 注册等规则套到 WhatsApp，也不得把模板审核逻辑套回 SMS。唯一共用的是**三渠道瀑布抑制与频控治理**（真源：本模块 `omnichannel-orchestration.md`）。
>
> **边界声明**：WhatsApp 商业政策、模板审核标准与计费口径变动频繁，以 Meta 官方当期文档为准（本文编制于 2026-07）；不构成法律意见，涉多国隐私法时请咨询专业人士。

---

## 1. 先判市场：该走 SMS 主线还是本分册

**WhatsApp 强适配**：LatAm / 东南亚 / 中东 / 南欧（WhatsApp 是默认通讯层）；客单较高、需要对话式转化的品类。**弱适配**：纯美国市场（渗透率低——走 SMS 主线，RCS 作为表现层升级观察项）。这是路由进本分册后的第一问，不适配就回主线，不要为建而建。

## 2. 两种消息、一扇窗口（WhatsApp 的核心机制）

| | 模板消息（Template） | 会话消息（Session） |
|---|---|---|
| 何时可发 | 任何时间（需预审核） | 仅用户最后一条消息后 **24 小时内** |
| 内容自由度 | 固定模板+变量 | 自由内容、无需审核 |
| 用途 | 营销触达、通知、召回 | 导购对话、客服、追问 |

**运营含义**：营销的本质是"用模板消息敲门 → 用户一回复即打开 24h 窗口 → 窗口内做对话式转化"。所有 Flow 都围绕"敲门-开窗-转化"三步设计。

**模板三类别**（计费与审核不同）：Marketing（促销/召回，审核最严）、Utility（订单/物流通知，通过率高）、Authentication（验证码）。**高频踩坑**：把营销话术塞进 Utility 模板会被重新归类甚至拒审；CTA 堆叠、全大写、缩短链是拒审高发原因。

## 3. 合规底座（先于一切增长动作）

- **Opt-in 必须显式**：结账页复选框、网站弹窗、短信/邮件引导添加——不得默认勾选，不得买号导入；记录 opt-in 时间与来源（同意留痕标准与 SMS 主线对齐，但法律依据体系不同）。
- **质量评级保护**：号码有质量分（用户拉黑/举报驱动），掉档即限流。频控参考起点：营销模板每用户每周 ≤2 条（内部经验估算，编制于 2026-07），旺季豁免与全渠道治理共用一套规则。
- **退出机制**：每条营销模板含退出指引，退出即时生效并同步全渠道抑制名单。

## 4. 三大核心 Flow（与 email/sms 瀑布规则对齐）

**F1 · Welcome（opt-in 后）**
```
[TRIGGER] 用户完成 WhatsApp opt-in
[TEMPLATE-Utility] W+5min 欢迎+首单利益（一条说清，别刷屏）
[IF 回复] → 24h 窗口开启 → 会话式导购（品类三问 → 推 2 款 → 结账短链）
[IF 未回复] → 交回邮件欢迎流主导，本渠道 7 天内不再主动触达
```

**F2 · 弃购挽回（与邮件/短信瀑布联动）**
```
[TRIGGER] 弃购事件
抑制检查：仅在「邮件 #1 已发且未打开 且 用户为 WhatsApp 活跃订阅者」时
  作为第二触点介入（T+6h）
[TEMPLATE-Marketing] 购物车提醒（商品图+价格+结账短链，一条）
[IF 回复"还在吗/多少钱"类] → 窗口内人话答疑 → 高意向未支付才给限时激励
瀑布铁律：同一弃购事件，email/sms/WhatsApp 合计 ≤3 次触达，任一渠道转化即全渠道停止
```

**F3 · 沉睡召回**
```
[TRIGGER] 90 天无购买 且 WhatsApp 质量分健康
[TEMPLATE-Marketing] 召回：新品/补货角度优先于折扣角度（对齐留存引擎折扣护栏）
[IF 回复] → 窗口内做需求重探（JTBD 三问）而非直接塞券
[IF 两轮无回复] → 标记渠道沉睡，转回邮件低频维系，勿再敲门
```

## 5. KPI 参考口径（治理式写法）

送达率、回复率（开窗率）、窗口内转化率、退出率、质量分趋势——以品牌自有基线为准；行业区间因市场/品类/名单质量波动极大，首月先建自己的基线。**回复率是本分册的北极星**：模板发出无回复＝没敲开门，优化永远先改敲门话术而不是加频次。

## 6. RCS：SMS 的富媒体升级（预告 / 试点）

- RCS 支持图片/轮播、按钮、已读回执、**验证发件人（品牌名+logo）**；Apple 自 2024 年底起支持 RCS，双侧打通后成为 SMS 的富媒体升级路径。
- **现状**：仍处"预告/试点"——运营商与设备覆盖、商家接入（多经 SMS 服务商）在铺开中，计费与可用性因市场而异。
- **与 SMS 合规的关系**：RCS 不替代 SMS 合规底线（同意/退订/10DLC 仍适用其体系，见 `compliance-checklist.md`）——把它当"表现层升级"而非新渠道另起炉灶。
- 来源：[MarTech：Apple/Google 2025 更新对 2026 email+SMS 的影响（含 RCS）](https://martech.org/what-apple-and-googles-2025-updates-mean-for-email-and-sms-in-2026/)。

## 7. 三渠道分工（一句话版）

邮件＝深内容与生命周期主干；SMS＝美国市场的时效触点；**WhatsApp＝对话式转化与高渗透市场的主触点；RCS＝SMS 的表现层升级观察项**。抑制与频控只有一套真源（`omnichannel-orchestration.md`），本分册不另立规则。
