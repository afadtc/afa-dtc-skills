# 赢品测试手册（测试店模式）

> 本文件为市场探索引擎的内部参考文件，用于 `supply_chain_mode = dropshipping` 且处于测品/测试店阶段（Hub 工作流 12 或用户自述测品）时的选品与验证。品牌模式的市场探索仍以 `core-paradigms.md` 与 `market-sizing-framework.md` 为主线。
> 如需整理为用户可见交付物，必须删除内部路由标签、模块代号和系统字段，只保留自然语言、业务角色与行动建议。
> 本文件中的经验阈值：来源＝内部经验 ｜ 采集窗口＝2026-10 ｜ 适用地区＝通用参考，须按目标市场与用户自身数据校准。阈值仅作逐品分诊起点（零数据期适用），不得当作行业统计写入交付物（基准治理规范见 `../../afa/_system/benchmark-governance.md`）。文中消费者文案示例为中文示意，交付时用目标市场语言（默认英文）。

## 1. 测试店范式（何时用本手册）

**核心逻辑**：品牌路径是"定位 → 产品"（先想清楚是谁，再决定卖什么）；测试店路径是"产品 → 定位"（先用低成本快速测出能卖的产品，赢家再进入品牌化）。两条路径互为镜像，终点相同——测试店跑出的赢家应进入品牌化流程（运营扩张组的 Dropshipping→DTC 过渡工作流：单位经济审计 → 私标 → 自有库存），再接回品牌基建组从品牌定位起的正式流程。

**测试店的合法性前提**（缺一即退回"低质铺货"，不可存活）：

1. 店铺具备品牌级质感（AI 建站已把这一成本降到小时级）；
2. 产品通过本手册的五标准 + 三层验证漏斗（不是盲目铺货）；
3. Offer 有真实价值堆叠（见客单价优化引擎 `../../afa-aov/references/bundle-strategy.md` §4）；
4. 素材与宣称合规（不编造评论/功效数字，见各模块反模式）。

**测试店建店纪律**（一次性决策，避免新手内耗）：

| 决策 | 规则 | 理由 |
|---|---|---|
| 品类 | 广义大类（家居/宠物/美妆个护/户外） | 可无限换品测试，产品死店不死（注意：宠物/儿童健康、美妆个护等类目在目标市场可能有前置要求，执行前确认相关规定） |
| 店名 | 无具体含义的简洁单词，勿用产品词 | 以产品命名的店死于第一个失败产品 |
| 域名 | .co 或 .com；被占用可加 try-/shop- 前缀 | 其他后缀损信任 |
| Logo | 黑白无衬线文字即可 | 头部品牌均为极简字标；勿在此耗时 |
| 主页 | 极简（横幅 + 精选集；评价区**仅在已有本店真实评价时启用**） | 流量入口是产品页，主页只是信任道具 |
| 导航 | Logo 链接指向主推产品页；砍搜索图标 | 单通道：广告→产品页→结账，减少游离 |
| 时间盒 | 建店整体 ≤1 天 | 时间应花在选品/验证/素材上 |

## 2. 赢品五标准（全中才准入）

| # | 标准 | 判定方法 | 常见误判 |
|---|---|---|---|
| 1 | **正在趋势中且正在出单** | 有竞对正为它持续投放（判定方法见 §5 L1；单店广告信号口径见竞争情报引擎 `../../afa-compete/references/ad-intelligence.md` §4）；勿自创产品概念 | "我觉得这个点子好"——无验证的自创想法是新手最大烧钱源 |
| 2 | **新/独特机制** | 对老问题的新解法。门槛可以很低：多一种成分、内置涂抹器、"2.0"式改良；也可**跨市场迁移**（同一产品换一个全新受众即构成"新"） | 大众已看腻的形态（经典切菜器、普通枕头）——见过=不停留 |
| 3 | **解决真实痛点** | 痛点三大域：**外貌 / 健康 / 金钱**（含宠物与孩子的健康）。越痛越好；人们偏爱"一步到位"式方案 | 玩具、小工具、电子小玩意——有趣≠痛 |
| 4 | **强 Wow 因子** | 在信息流中 3 秒内能停住滚动（视频或静态图均适用）；受众来自高刺激信息流，产品本身要有视觉戏剧性 | 静态无演示价值的日用品 |
| 5 | **≥3 倍加价空间（单品准入下限）** | 售价 ≥ 履约成本×3；**履约成本 = 货价 + 国际运费 + 代发服务费 + 目标市场关税/税费 + 赠品成本**（关税税费口径用全渠道扩张引擎 `../../afa-expand/scripts/landed_cost.py`；税务事项建议咨询专业人士）。测试期最便宜 SKU 也应有约 $30 毛利以覆盖买量。**若计划做买 2 送 1 + 赠品类 Offer，需 ≥5 倍加价**（算术见客单价优化引擎 bundle-strategy §4） | 只看百分比不看绝对毛利额；漏算关税与赠品 |

**四排除**（任中一条直接否决）：

1. **线下随手可买（同款即得）**：普通商超随手可得的同款 → 无"此时不买再无此价"的紧迫感基础。注意与 §5 L2 的分界：**电商平台存在同类**是需求证据，**线下同款即得**才是紧迫感缺失；
2. **品牌/版权元素**：IP 形象、明星、品牌联名仿品 → 大概率遭投诉下架，且存在知识产权风险（执行前确认相关规定）；
3. **擦边性用品**：广告平台先给量后封号；
4. **新手不碰入口消耗品/补剂**：责任风险高且饱和。外用贴片/涂抹类的风险通常低于入口品，但**本手册 §5 的否决案例恰是一款保健贴片**——此类产品同样须过 L3 风险筛查，不得视为免检通道。

**辅助杠杆——顺季选品**：测试期顺应当季（夏测降温、冬测保暖），与全渠道扩张引擎的反季套利（`../../afa-expand/references/trend-timing-arbitrage.md`）互补：测品要顺季吃现成需求，囤货套利才反季。多国投放时注意南北半球季节相反（见 Meta 广告引擎 Day-0 结构的地理前提）。

## 3. 竞对执行质量评估（可超越空间法则）

产品已验证 ≠ 可以进。还要评估**在跑这个产品的竞对店铺执行质量**：

- 竞对店铺一般（图粗糙/无 offer/文案偷懒/单位未本地化）→ **最佳进入点**：产品已验证 + 执行可超越；
- 竞对 offer/图/页全部拉满 → 新手回避，另寻目标；
- 竞争的最小单元不是产品而是执行。测试店竞争靠累积小优势：价格低几刀、多一件赠品、多一个尺码、把竞对的摄氏度改成华氏度——每个小优势都要拿。

**跟品 ≠ 模仿**：本手册验证的是"需求已被市场证明"，执行层必须做差异化（与本模块反模式中的"竞品模仿陷阱"一致，见 `anti-patterns.md`）。

单店广告信号分诊带与轨迹信号见竞争情报引擎 `../../afa-compete/references/ad-intelligence.md` §4。

## 4. 选品信息源（按可控性排序）

1. **广告库过滤法（首选；多为付费工具）**：用广告情报工具按"活跃 + 近 30 天创建 + CTA 为 Shop now/Order now + 目标国+英语 + 单页活跃广告 20-75 条 + 业内常用主题指纹"组合过滤，信息流即只剩同行在跑的已验证产品。逐条按五标准初筛，候选入清单。
2. **信息流训练法（免费备选）**：用**本人**社交账号对信息流里每个产品广告执行点赞/评论/进店/加购，数日内把信息流训练成免费选品雷达（勿虚构身份账号，账号条款以平台官方现行规定为准）；见到候选 → 页面透明度 → 广告库查其活跃广告数与首投日期。缺点：不可控、不稳定，只作预算为零时的替代。
3. **短视频电商榜单**：TikTok Shop 同类产品销量（"X sold"）既是选品源也是验证数据（见 §5 L2）。

## 5. 三层零广告费验证漏斗（全过才花广告费）

> 纪律：五标准全中 + 三层全绿之前，不进入建页与投放。宁可多花一天验证，不烧一周广告费。

**L1 广告持续性验证**：
- 该竞对（或任一其他店）为此产品**持续投放 ≥1.5-2 周**——没人给亏损广告续费，持续投放≈在赚钱（这是单品广告级口径；品牌级的"投放 >6 个月=正向模型"口径见竞争情报引擎 `../../afa-compete/references/benchmarking-playbook.md`，两者分层）；
- **近几天仍在上新广告** = 强绿灯；多店同投同品 = 更强验证；
- 若该店铺广告分散在多个产品上，以**该产品对应的广告数**计，不按店铺总数；
- 广告**突然全停**：既是机会窗口（需求真空），也是警示信号（可能封号/断供=该品有合规或履约隐患）→ 必须走 L3 加严核查。

**L2 跨平台需求量验证**：
- Amazon 同类多个 listing 显示月购件数（平台展示口径），出现多个数百至数千级 listing = 需求实证；
- **搜不到同类**有两种解读：需求尚未到达（全渠道扩张引擎趋势时机口径，`../../afa-expand/references/trend-timing-arbitrage.md`）或宣称可疑——两种情况一律加严 L3；
- 顺带读 Amazon 差评：均分 3 星左右 = 产品无法兑现承诺，否决；1-3 星差评内容 = 你的改进机会清单（与产品策略引擎"竞品差评=你的PRD"同法）；
- TikTok Shop 同品销量数为旁证；
- 1688/Alibaba 核货价，连同运费/税费/赠品核五标准第 5 条。
- 口径注：竞争情报引擎四维密度表把"同品类评论数 >500"判为品类红灯（赛道进入决策），本层把"多 listing 月购数千"读作需求实证（逐品决策），两者对象不同，见该表口径注。

**L3 AI 深研风险筛查（非合规裁决）**：
- 把竞对产品页 URL 交给具备联网深度研究能力的 AI，要求输出**风险事实卡**：真实需求、宣称可兑现性、季节性与生命周期、以及支付通道/广告平台/监管类目（如涉及健康功效宣称）的风险信号；
- 本层的价值在于抓 L1/L2 看不见的风险——示意案例：某保健贴片 L1/L2 全绿（数十条活跃广告、多 listing 月销数千），因"承诺无法兑现 + 支付与广告平台风险信号"被放弃；
- 判读纪律：**AI 结论不构成合规确认**，命中监管/知识产权类风险信号时，事实卡附"执行前咨询专业人士"的升级触发器（遵守铁律 11）；**出现高风险信号且未经专业确认则不进入下一步**；AI 放行 ≠ 保证成功；
- 本层对品牌模式同样适用（可并入产品验证实验清单）。

**验证通过后的出口**：→ 产品上市引擎模式 F 测品快速通道（`../../afa-launch/SKILL.md`：48 小时上线清单与判读规则）；页面与 Offer 由变现留存组承接（转化率优化引擎 `../../afa-convert/references/ai-page-rewrite-sop.md`、客单价优化引擎 `../../afa-aov/references/bundle-strategy.md` §4）；投放结构见 Meta 广告引擎 `../../afa-fb/references/day-zero-testing.md`。

**最小测品档案（本模式对下游的交付物）**：验证通过后由本模块写入 Brand Brain——`products.md` 补一条候选品条目（产品、履约成本口径、目标售价、验证结论），`audience.md` 补客户语言摘要（§6）。下游模块在测品阶段以此替代品牌模式的完整产品矩阵与声音档案。

## 6. 快速客户语言提取（测品节奏版 VOC）

深度 VOC 六源体系见 `voc-mining-playbook.md`（品牌模式）。测品节奏下用 10 分钟轻量版：

1. 用具备联网抓取能力的 AI 运行"客户语言提取"研究：输入 = 候选产品 URL + 品类 + 目标国 + 2-3 个竞对 URL（**选评论数最大的 Amazon listing**）+ 最大相关社区（如相关 subreddit）；
2. 要求输出：客户**原话**词库（每条附来源链接；AI 未能给出来源的标"假设"，不得当作原话使用）、渴望与痛点短语、竞对卖点拆解、一页摘要（示意产出："买家要的不是配件，是不想再看着宠物喘气"——可转为广告头图文案的方向）；
3. 产出存为该产品的上下文资产，供素材与文案环节复用（见创意生产引擎 `../../afa-creative/references/dropshipping-ads-playbook.md`）。
