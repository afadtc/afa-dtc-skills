> 本文件为转化率优化引擎的内部参考文件，用于两件事：①用 AI 对 Shopify 产品页模板做整页结构化改写（省 1-2 小时/页）；②`supply_chain_mode = dropshipping` 测品场景的信任基建组件清单。页面内容标准仍以 `landing-page-playbook.md`（落地页 12 模块）与 `core-frameworks.md`（PDP 九段式）为真源，本文件只解决"如何用 AI 高效落地"。

## 1. AI 整页改写 SOP（模板 JSON 工作流）

**适用**：Shopify 类建站工具的区块化页面（主题模板以 JSON 描述区块与文案）。**核心收益**：从"逐区块手写文案"变为"AI 一次性重写整页"，10-15 分钟完成原本 1-2 小时的工作。

**八步流程**：

1. **先搭骨架**：在主题编辑器按 PDP 九段式排布区块——首屏黄金区 / 核心卖点 / 产品故事 / 社证（仅真实评价，无则留空或隐藏）/ 规格 / 异议与风险逆转 / 交叉销售 / 信任保障 / 粘性加购栏（对比表属核心卖点段的可选组件），文案先留占位；
2. **模板独立化**：为该产品创建独立模板（勿直接改默认模板），从代码编辑器整份复制模板 JSON；
3. **备份原 JSON**：改写前把原模板 JSON 另存一份，便于改坏时整份回滚；
4. **建 AI 项目**：为该产品建一个持久对话项目（系统指令="你是本产品的文案与转化专家"），JSON、客户研究、图片素材全部沉淀在此项目内——**上下文资产化**，后续图片标题、广告文案复用同一项目；
5. **先理解后改写（可靠性关键）**：第一步只让 AI"完整理解这份 JSON 的结构与布局，暂不改动"——跳过此步直接改写，大概率破坏页面结构；
6. **喂参照物**：提供竞对产品页 URL + 评论数最大的同类 Amazon listing URL，让 AI 提取最佳文案元素与角度（原则：**借结构与角度，禁逐句照抄**，见 §4 红线表）；
7. **改写与回贴**：让 AI 按九段式标准重写 JSON 中全部文案 → 整份复制回主题代码编辑器 → 预览检查（重点：变体/价格区未被改坏、无结构错乱）；
8. **人工终审**：AI 初稿必带"机器味"，逐段用人话修（迭代时告诉 AI"只讨论文案方案、先不重生成 JSON"，避免每轮全量输出）。

**执行纪律**：
- 复杂任务（整页 JSON 改写）用高能力模型档；琐碎任务（改价、换词）切低档快速模型——省时省费；
- **反幻觉护栏（铁律级）**：AI 产出中出现的一切数字（百分比、样本量、"X 人已购"、功效数据）必须替换为品牌可出示来源的真实数据，写不出来源就删——常见做法在此处高频违规（见 §4）。

## 2. 首屏细节武器库（测试店场景补充）

以下为首屏黄金区（`core-frameworks.md` PDP 段 1）在测品场景的补充清单：

| 项 | 规则 | 备注 |
|---|---|---|
| 卖点条 | 每行一句、一行放满不换行、只讲收益不讲功能 | 示意："终结不停喘气" ✓，"机洗方便" ✗（改写为"几分钟恢复清爽"） |
| **单位本地化** | 按主市场用本地单位（美国：℉/lbs/inch；多国投放时双标） | 竞对常偷懒留公制——**白捡的执行优势** |
| 标题公式 | 品牌产品名 + "—" + 关键词描述 | 关键词描述参考头部 Amazon listing 用词（天然词库）；"2.0"后缀可暗示新机制（须对应真实改良） |
| 尺码/规格命名 | 带使用者参照（示意："Small – up to 11 lbs"） | 降决策成本与退货 |
| 变体极简 | 砍非必要颜色/规格；多规格用下拉 | 结账前每多一个决策都在漏水 |
| 社证行 | 仅在有可证数据时使用，零评价期省略 | 见 §4 红线 |
| 支付图标 | 只留主流卡 + 本地主流 + 分期 | 图标也是信任语言，杂牌图标减分 |

## 3. Dropshipping 信任基建包（上线前置件）

长时效履约的焦虑必须用基建对冲。以下组件在**首个广告上线前**全部就位（兼作广告平台站点审查的合规前置件）：

1. **订单查询页**：独立物流查询页（如 17TRACK 类工具的免费查询页）挂主导航"Track Your Order"——把"我的货呢"从客服工单变为自助查询（引用客户体验引擎的物流静默期防御：`../../afa-cx/references/cx-automation-toolkit.md`）；
2. **动态预计送达组件**：产品页展示按当日自动计算的送达区间（min-max 天数如实填写；多国投放时按国家取值）——透明时效本身就是转化要素（本模块结账八原则第 6 条"配送透明"的组件级落地）；
3. **运费双轨**：测品期默认**免运费**——这是 dropshipping 测品的例外口径：**意外的额外费用（含运费）是第一大弃单源**（`../../afa-aov/references/cart-abandonment-recovery.md`），而客单价优化引擎的免邮门槛体系（`../../afa-aov/references/threshold-engineering.md`）面向已有订单数据的品牌，测品期无众数 AOV 可定门槛，跑出赢家后再切回门槛制。可另设一档付费运费选项，前提是**对应真实的差异化服务**（优先线路或丢件赔付），按真实线路时效与赔付率定价、净贡献为正，名称不夸大（没有真实加急线路不叫 Express）；
4. **政策页全套**：隐私 / 条款 / 退款 / 发货政策（发货政策如实写处理与运输时长）——广告平台会扫描站点，缺失即拒审或限流；
5. **测试订单**：上线前用测试模式完整走一遍结账，确认支付/邮件/订单流转正常。

## 4. 合规红线与替代方案（本 SOP 场景高发）

| 红线 | 常见违规做法 | 合规替代 |
|---|---|---|
| **编造社证** | AI 直接生成"用户好评"、评价拼图、凭空的"15,000+ 满意客户" | 上线初期宁可不放社证区块；用购后邮件/短信自动化快速积累真实评价（邮件营销引擎与 SMS 营销引擎已有全套流程）；社证数字只用可证口径并注明出处。虚假评论在主要市场面临监管处罚与平台封店风险，并连带支付通道风控 |
| **逐句照抄** | 把竞对或 Amazon listing 文案整段搬运 | 只借结构与角度，用自己的客户语言重写（§1 第 6 步） |
| **假紧迫** | 永久性"今日截止"倒计时 | 真实档期/真实供给窗口的紧迫机制；可用真实的稀缺陈述（如"一般商超买不到"，前提是陈述属实）替代倒计时 |
| **无据功效数字** | "降温 X 度不然免费"式未经证实的量化承诺 | 保留"结果承诺 + 退款兜底"句式外壳，数字换成可出示的检测报告（并自行抽检）或可引用来源，否则降级为定性承诺 |
