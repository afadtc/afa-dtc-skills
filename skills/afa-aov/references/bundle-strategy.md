# 捆绑销售架构 (Bundle Architecture)

捆绑销售是提升 AOV 的核心杠杆。它不仅能增加单笔订单的收入，还能通过组合高利润配件来保护整体毛利率，同时降低单件商品的履约和物流成本。

## 1. 捆绑销售的三大核心模型

### 1.1 入门套装 (Starter Kit)
**目标**：降低新客户的决策门槛，提供完整的初始体验。
**结构**：1 个核心产品 (Hero Product) + 2-3 个互补配件。
**定价策略**：通常提供 10%-15% 的折扣。
**适用场景**：
- 需要配件才能发挥最佳效果的产品（如：电动牙刷 + 刷头 + 旅行盒）。
- 护肤品的“基础三步曲”（洁面 + 爽肤水 + 面霜）。
**价值主张**：“一站式解决你的所有需求，比单买更划算。”

### 1.2 囤货装/补充包 (Replenishment Bundle)
**目标**：针对消耗品，提前锁定未来的复购需求，推高当次 AOV。
**结构**：同一产品的多件装（如 3 件装、6 件装）。
**定价策略**：阶梯折扣（买 2 件 10% off，买 3 件 20% off）。
**适用场景**：
- 营养补充剂、洗发水、咖啡豆、隐形眼镜。
**价值主张**：“买得越多，省得越多。反正你迟早要用完。”

### 1.3 策展系列 (Curated Collection)
**目标**：针对送礼场景或特定主题，创造高感知价值的组合。
**结构**：跨品类的相关产品组合，通常包装精美。
**定价策略**：强调“套装总价值”，提供 15%-20% 的折扣。
**适用场景**：
- 节日礼盒（如“母亲节奢宠套装”）。
- 场景化组合（如“夏日海滩防晒系列”：防晒霜 + 晒后修复 + 太阳镜）。
**价值主张**：“为你精心挑选的完美组合，送礼自用两相宜。”

## 2. 混合利润率计算 (Blended Margin Logic)

设计捆绑包时，最大的风险是“折扣吃掉了所有利润”。必须计算混合利润率，确保其高于品牌的最低可接受毛利率（**建议目标线通常为 60%**）。

> **两条线，别只记一条**：**60% 是建议目标线**（未达 → 提示并说明利润让渡换到了什么），**50% 是红色警戒线**（跌破 → 必须红色警告、提价或换品，见 `anti-patterns.md`）。分套装型的底线区间（55-65%）见 `benchmark-data.md` §捆绑包类型。量化判定用 `../scripts/promo_breakeven.py bundle`（三档 PASS / WARN / FAIL）。

### 2.1 计算公式
`混合毛利率 = (捆绑包售价 - 包含所有单品的总 COGS) / 捆绑包售价`

### 2.2 示例分析
假设你有一个核心产品 A 和一个配件 B：
- **产品 A**：售价 $100，COGS $40（毛利率 60%）
- **配件 B**：售价 $30，COGS $5（毛利率 83%）
- **单买总价**：$130
- **单买总 COGS**：$45
- **单买混合毛利率**：($130 - $45) / $130 = 65.4%

**设计捆绑包（提供 15% 折扣）**：
- **捆绑包售价**：$130 * 0.85 = $110.5
- **捆绑包总 COGS**：$45（不变）
- **捆绑包混合毛利率**：($110.5 - $45) / $110.5 = **59.3%**

**结论**：虽然提供了 15% 的折扣，但由于配件 B 的超高毛利率（83%）拉高了整体水平，捆绑包的混合毛利率依然保持在健康的 59.3%（接近 60% 的底线）。这就是为什么捆绑销售必须包含高利润配件的原因。

## 3. 捆绑销售的 UI/UX 最佳实践

1. **产品页 (PDP) 上的“经常一起购买” (Frequently Bought Together)**：
   - 在核心产品的“加入购物车”按钮下方，直接展示 1-2 个互补配件。
   - 提供一键将所有商品加入购物车的选项，并明确标示组合购买的折扣金额（如“一起买省 $15”）。
2. **构建专属的捆绑包落地页 (Bundle Landing Page)**：
   - 对于“策展系列”或“入门套装”，不要只在单品页追加，应该为其创建一个独立的落地页，详细阐述套装的整体价值。
3. **“构建你自己的套装” (Build Your Own Bundle, BYOB)**：
   - 允许客户从特定类目中挑选 3-5 件商品，达到数量后自动解锁阶梯折扣。
   - 这种方式赋予了客户控制感，极大地提高了转化率和 AOV。

## 4. 测品场景的 Offer 工程（Dropshipping 适配）

> 适用：`supply_chain_mode = dropshipping` 的测试店产品（变现留存组工作流 E 承接）。与本文件其余章节的差别在定位：常规捆绑是给存量品牌提客单，本节的 Offer 是给可比价商品**建竞争护城河**。混合毛利红线（50%）与目标线（60%）继承 §2，不另设口径。本节数字：来源＝内部经验 ｜ 采集窗口＝2026-10 ｜ 适用地区＝通用参考。文案示例为中文示意，交付时用目标市场语言。

**核心问题**：顾客在大型电商平台明天就能买到同款，凭什么现在从你这买？答案不是降价，是 Offer 堆叠制造"此时此地才有"的价值差：

1. **结构**：数量阶梯三档（买 1 / 买 2 送 1 / 买 3 送 2），中档为**推荐档**默认选中——各档价格明示、一键可切换、不预勾任何附加收费项；零销量期标"推荐"或"最划算"，有真实销量数据后才可标"最受欢迎"；+ 每档 1-3 件免费赠品（加购时自动以 $0 显示入车，"零元感"本身就是转化器）；+ 可证的参照价锚点（新店无历史售价时只用可核的市场参照价，不虚标划线价）；+ 真实档期的限时；
2. **赠品选法**：去头部平台同品类最大 listing 的关联购买区找（买家已投票的互补品）；标准=履约成本低（约 $5 内）+ 独立标价须有可核的市场参照（示意：$9.99 档）+ 贴合主卖点角度；**实物赠品须与主品同一供应商可合单发货**（否则多包裹=多倍运费与时效风险），做不到则改**数字赠品**（使用指南 PDF / 社群资格 / 教程视频：零成本，且是本模块 `anti-patterns.md` §3 Dropshipping 适配的首选）；
3. **算术纪律（先过校验再上线）**：捆绑价取整（$79.99 而非算出的 $76.50）；**默认档必须过 `../scripts/promo_breakeven.py` bundle 模式校验（混合毛利 ≥50% 红线，目标 60%）**。警示算术：单品加价仅 3 倍（履约成本 C、售价 3C）时，买 2 送 1 的混合毛利 = (2×3C − 3C) ÷ (2×3C) = 50%，恰好压线，再加 2 件 $5 赠品即跌破红线——因此**买 2 送 1 + 实物赠品结构要求单品加价 ≥5 倍**；加价不足时改"买 2 享折扣 + 数字赠品"或只送 1 件低成本赠品。**旗舰捆绑毛利须覆盖目标获客成本且有余**——Offer 设计直接决定广告预算空间（盈亏平衡 CPA = AOV × 毛利率，推理规则真源不变；履约成本按含运费/税费/赠品的完整口径，见市场探索引擎赢品测试手册五标准第 5 条）；
4. **验证信号**：测试期看买家的**主动切换率**（从默认档切到更高或更低档的比例），而非默认档占比（默认效应会污染后者）；高档的主动选择率高 = Offer 结构成立，是比单量更早的正向信号。

红线：赠品价值必须真实（虚标参照价/凑数废品会转化为退款与差评）；限时必须真实（假倒计时属本模块 `anti-patterns.md`「禁止虚假稀缺性」）；代发模式下不得以"真实库存紧迫"为由造稀缺——可用真实供给窗口或真实档期。
