# 支付账户冻结应对 SOP（Stripe / PayPal / Rolling Reserve）

> 本文件为支付风控模块的内部参考文件。如需整理为用户可见交付物，必须删除内部路由标签、模块代号和系统字段。
>
> **边界声明**：本文件是运营应对流程参考，不构成法律或财务意见；各平台风控政策与期限以其官方当期通知为准（本文编制于 2026-07）。涉及大额资金、合同纠纷或平台申诉僵局时，请咨询专业律师或持牌顾问。

## 1. 先识别你遇到的是哪一种（处置完全不同）

| 类型 | 典型形态 | 资金状态 | 常见期限口径 |
|---|---|---|---|
| 风险审查暂停 | 收款暂停 + 要资料 | 余额暂锁 | 数天-数周，补齐资料为主 |
| 余额冻结/延迟结算 | 可收款但不放款 | 滚动延迟 | 常见 30-120 天观察期 |
| PayPal 临时限制 | 功能受限 + 补材料 | 部分可用 | 常见 21 天放款保留 |
| 账户终止 + 长冻结 | 关户通知 | 全额冻结 | 常见 180 天后分批释放 |
| Rolling Reserve | 正常经营附加条款 | 按比例滚动保留 | 如 10-15% 保留 90 天（以协议为准） |

> 以上期限为行业常见口径（内部经验估算，编制于 2026-07），**一切以你账户后台通知与协议原文为准**——第一步永远是把平台通知原文完整读三遍。

## 2. 黄金 72 小时 SOP

```
H0-2   截图存证：通知全文、后台余额、未决订单清单（此后界面可能变化）
H2-12  判型（对照 §1）→ 停止一切"申诉前的情绪化联系"——每次低质量申诉都在消耗信任
H12-24 组申诉材料包（见 §3），一次性交齐 > 挤牙膏
H24-48 通过官方申诉通道提交；同步启动现金流预案（见 §4）
H48-72 客服与物流侧动作：未发订单决定"照常履约/暂停接单"；
       照常履约是多数审查场景的加分项——停摆反而坐实风险判断
```

**三条铁则**：①绝不注册新账户"绕过"冻结——关联检测会连坐并坐实违规；②绝不改动在途订单的履约承诺——冻结期争议率上升是二次死刑；③所有沟通走官方工单留痕，电话沟通后补一封书面摘要。

## 3. 申诉材料包（通用清单）

营业与身份证明（执照/法人证件/地址）□ 供应链凭证（采购发票、供应商合同——证明"你真的有货"）□ 履约证明（近 90 天带追踪号的发货记录批量导出）□ 库存照片/仓库视频 □ 争议与退款处理记录（体现你在积极处理售后）□ 网站合规截图（退货政策/联系方式/条款页）□ 资金用途说明（如被问及）□ 一页纸经营概述（业务模式、客单、主力市场、月单量——让审核员 3 分钟看懂你是真实生意）□

## 4. 现金流预案：Rolling Reserve / 冻结推演（可复算示例）

设月收款 $60,000、月固定支出 $9,000、广告月投 $15,000：

- **场景 A · 10% 保留 90 天**：每月被保留 $6,000，第 4 个月起每月同额释放；稳态占压 = $18,000。相当于常备 0.3 个月收款的额外营运资金——可承受，但需把广告回收期控制在 60 天内。
- **场景 B · 全额冻结 120 天**：立即失血 = 月收款 100%。生存算术：现金储备需 ≥（固定支出 + 必要广告 + 供应商刚性付款）× 4。本例最低 ≈ ($9,000 + $7,500 + 货款) × 4——广告砍半仍需备 $66,000+。**结论：单通道收款 + 现金储备 < 3 个月支出 = 系统性脆弱。**

推演口径：保留占压 = 月收款 × 保留比例 × (保留天数/30)；释放后转为滚动中性。把你的数字代入即可，或交由运营模块的单位经济脚本连同六层成本一起算。

## 5. 结构性预防（把"会不会被冻"变成可管理变量）

- **收款多通道**：主通道之外常备一条已过审的备用通道（不同处理商体系），流量 90/10 保温——不是为了绕规则，是为了单点故障不致命。
- **争议率红线**：VAMP 口径 <0.9% 起黄灯自查（`../scripts/vamp_check.py`），高风险期主动降速扩量。
- **风控画像友好化**：账单描述符可识别、追踪号 100% 回传、退款响应 <48h、避免收款金额结构突变（大促前给通道方提前报备是被低估的动作）。
- **协议自查**：入驻时就看清保留条款与终止条款——Rolling Reserve 比例与期限是可以随账户历史良好而谈判下调的。
